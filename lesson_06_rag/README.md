# 第 6 课：迷你 RAG —— embedding + 向量检索 + 重排

## 知识点清单

1. **为什么需要 RAG**：模型只知道训练时见过的 + 你放进上下文的。
   私有知识/最新知识，重训太贵，RAG 用"查资料 + 誊写进上下文"解决
2. **embedding**：文本 → 向量，语义相近 → 向量夹角小（余弦相似度）。
   本课手写 bigram 哈希向量做教学替身，懂"字面像"不懂"语义像"，
   与真实模型（BGE 等）机制同构：换 `embed()` 一个函数即升级
3. **检索**：全部向量算余弦 → 排序 → top-k（生产 = FAISS/Milvus 等向量库）
4. **重排（rerank）**：粗召回用向量找"像"，精排找"对"；
   本课用字面重合度模拟，生产用 cross-encoder
5. **防幻觉三件套**：仅限资料作答 + 引用编号 + 没有就说没有
6. **命门**：检索错则全错 —— 分块策略与检索质量决定 RAG 上限

## 练习（做完才算过关）

1. 往 `DOCS` 里加 5 条自己写的"私有知识"（比如你们组的规范），再问
   相关问题，验证检索与引用编号。
2. 把 `retrieve` 的 top_k 改成 1，问一个跨两条知识的问题，观察答不全
   —— 体会 top_k 是召回率与噪音的权衡。
3. （进阶）把 `embed()` 换成真 embedding API（如 SiliconFlow 的 BGE，
   OpenAI 兼容格式），重跑 01 的第 3 个查询"让 AI 帮我调用外部程序"，
   观察语义检索的差距。
4. 思考：文档很长时为什么要切块（chunk）？块太大/太小各有什么问题？
