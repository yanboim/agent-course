# 第 4 课：真实工具 —— 文件 / 命令 / HTTP + 安全与错误处理

## 知识点清单

1. **模型输出永远不可信**：它可能给出 `../../etc/passwd`、`rm -rf`、
   非 https 链接。安全边界必须由**代码**强制，不能靠 prompt 恳求
2. **路径监狱（jail）**：resolve 后检查是否仍在沙盒目录内，
   越界一律拒绝（任务 2 现场演示被拦）
3. **命令白名单**：`shlex.split` + `shell=False` + 白名单 + 超时 + cwd 钉死
4. **工具永不抛异常**：一切错误转成 `ERROR: ...` 文本作为 tool 消息回传，
   模型读到错误会调整策略 —— 这是 Agent 韧性的来源
5. **返回值一律字符串 + 截断**：防止一个巨大输出撑爆上下文

## 练习 4 答案：为什么工具返回前要截断？

工具结果会原样进入 messages，下一轮起每轮全量重发。不截断的后果链：

1. **撑爆上下文窗口**：10MB 文本 ≈ 数百万 token，远超任何模型的窗口上限，
   直接 400 报错（`maximum context length exceeded`）——对话当场死亡；
2. **费用爆炸**：即使窗口够大（长上下文模型），这几百万 token 每轮都要
   重新计费，一次 `cat` 可能烧掉几十块钱；
3. **延迟劣化**：prompt 越长首 token 越慢，交互体验崩坏；
4. **注意力稀释**：就算塞得进、付得起，超长上下文里模型找关键信息的
   精度也会下降（大海捞针问题）。

而工具结果的信息密度往往集中在开头（错误信息、状态行、列表头部），
所以本课统一策略：`read_file` 截 2000 字、`run_command` 截 1500 字、
`http_get` 读 2000 字节。要更多？让模型带着分页参数再要（这是第 5 课
上下文管理思想在工具层的提前应用）。
