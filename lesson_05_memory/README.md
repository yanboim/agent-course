# 第 5 课：Memory —— 上下文管理：裁剪、摘要压缩、长期记忆

## 知识点清单

1. **token 贪食蛇问题**：Agent 每轮全量重发历史 → prompt token 线性暴涨
   （钱）+ 终会撞上下文窗口上限（崩）
2. **滑动窗口**：只留最近 K 条。便宜、简单，但**失忆**：被裁的不是垃圾
   是记忆 —— 01 例现场演示翻车
3. **摘要压缩**：老对话先压成摘要再丢弃原文。省钱且保住关键事实，
   但有损 + 摘要调用本身要花钱
4. **长期记忆（思想）**：关键事实抽成键值对存外部（文件/数据库），
   需要时检索注入上下文 —— RAG 的思想用在"记忆"上
5. 完整记忆架构 = 短期（原文最近几轮）+ 中期（滚动摘要）+ 长期（外部存储）

## 练习 4 答案：为什么摘要以 user/assistant 对放回，而不是并进 system？

先承认事实：**协议上并不禁止**把摘要塞进 system（03 例甚至把记忆注入
system）。用 user/assistant 对是工程惯例，理由有四：

1. **通道语义**：system 是"应用开发者下的常驻指令"，user/assistant 是
   "对话里发生过的事"。叙事性摘要的本质是【对往事的追述】，放进对话
   通道，模型会给它正确的"认知身份"——这是回忆，不是指令。混进
   system 容易产生指令漂移：模型把"你说要顺丰到付"当成"现在必须做
   什么"来执行。
2. **事实 vs 叙事的分界**：03 例注入的是短语级键值事实
   （订单号=A-1024），读起来像"已知背景"，放 system 很自然；02 例的
   摘要是成段叙事，保留对话形态更利于模型沿用"我们聊过"的口吻接话。
   短事实进 system、长叙事进对话通道，是常见分工。
3. **可维护性**：system 只有一个、且永远在第 0 位。每轮重写 system
   字符串拼接摘要，指令与记忆搅在一起，出问题时难以定位是哪个通道
   引起的；分开则各自的变更独立可测。
4. **训练分布**：模型见过的对话语料里，"前情回顾"大量以对话形式
   出现；system 位置的内容几乎总是指令。顺着训练分布走，表现更稳。
